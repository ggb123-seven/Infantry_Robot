# 拨弹实际到位后逐发推进验证

日期：2026-11-04

## 操作与本轮变更

用户确认按实际完成反馈逐发推进，实施方案见 ../workflows/2026-11-04_feeder_single_step_plan.md

1. 右拨杆先到下位，再将左拨杆从非上位切到上位，选择单发
2. 右摇杆先回中，再向上推到端部，触发固定一齿，当前为输出轴 45°，方向沿用 config.direction=-1
3. 执行期间不追加目标；长推在本发实际到位且满足启动间隔后重复下一齿，短推松杆完成当前一齿
4. 左拨杆离开上位选择连发并等待回中；右拨杆退出下位、遥控失联或非法右拨杆撤驱
5. 角度连续性丢失、反馈超过 10 ms 无新帧或本周期命令缺失撤驱并取消旧步骤，恢复时捕获当前位置且重新要求回中

向上端部沿用现有右摇杆 ch_r_y 为负的约定，归一化值不大于 -0.95 触发，原始计数约不大于 -629。中心死区继续为 5%。摩擦轮依旧由右拨杆运行档独立使能，不随每发到位停止

到位判据为 M2006 减速后输出轴的环绕角度误差绝对值不超过 0.5°、绝对转速不超过 1 rpm，连续保持至少 20 ms；条件任一中断即重新累计稳定时间。本发启动超过 1 s 未完成则锁存 FEEDER_FAULT，电流由 Feeder_DumpOutput 归零，待机档解除

重复进给最短启动间隔取 1/feed_hz，当前配置为 20 Hz，即至少 50 ms。若实际到位更慢，等待实际到位。目标每次从上一齿目标递增并归一化到一圈，禁止从实测位置反复追加未完成的 45°

## 接口与兼容性

- 按确认的 A 方案新增 Cmd_Feeder_t，上下文由 Task_motor_trigger 独占；命令层负责拨杆顺序、回中和向上端部电平
- Feeder_Command_t 增加 fire_mode、single_fire；既有 mode、speed_ratio 保留。Cmd_ParseFeeder 增加上下文参数，所有生产调用方已同步
- Feeder_Internal_t 增加 single_state、step_elapsed_s、settled_s，运动执行、到位、间隔和超时集中在模块内
- feeder_fire_mode 和 feeder_angle_target_deg 改为观测，控制不读取这两个可写调试符号，写入会被实际状态覆盖。模式 1 的历史手动目标角调试行为被本轮遥控逐发替代
- Feeder_t、Feeder_Config_t、config.c 未修改；feeder.config 可写副本、周期配置快照及 PID 对持久 cycle_config 的引用保留
- 连发保留双向速度环，单发才要求角度连续。摩擦轮原有目标和发布逻辑未修改
- 遥控最新状态邮箱仅提供实际消费到的先后状态，不保证恢复被覆盖的每次物理拨动；若未观测到完整顺序，不从最终档位组合推断先后

- 通过 RAM 副本修改 feed_hz 为 2 验证 500 ms 间隔不可由松杆再推绕过；执行中反复修改速度 PID 仍在超时后锁存故障
- 精确 ±0.5° 比较用例在弧度转换后直接设置公开角度观测以隔离浮点表示舍入；其余角度窗口用例输入弧度反馈，验证 ±0.49° 通过、±0.51° 不通过

## 三层复核

验证门：上述真实生产代码编译、主机行为回归和 ARM 构建通过。本轮没有烧录、复位、写目标 RAM、读取实时变量或真实电机试验

硬件合规：未改变 CAN ID、引脚、时钟、DMA、中断、CubeMX 或设备驱动，不增加硬件资源；ARCH/HW/SPEC 检查结果在同名 JSON 中保存。arch-check 的资源表专项因仓库没有硬件资源表而跳过，不把脚本 PASS 当作新增实物验收

代码质量：仍为 task → module → component/device；main、RTOS/HAL 对象创建及 ISR 均未修改，不新增临界区或中断共享状态。任务独占命令上下文，单发执行状态归模块独占，所有电流仅由 Feeder_DumpOutput 放行。两个 PID 继续引用持久配置快照；配置无效、反馈不可用及超时时不执行后续有效输出

## 检查自查

本轮未新增实例判空、isfinite 或配置字段有效性检查。命令输入缺失检查保留在 Control 入口一次，通过本周期命令快照统一处理，删除原来多处 command != NULL 的重复判断

| 新增条件或提前退出 | 分类及真实场景 | 上游是否检查同一条件 |
| --- | --- | --- |
| 右摇杆比例不大于 -0.95 | 命令业务触发条件，区分向上端部与其他摇杆位置，不是重复协议范围校验 | 无，DR16 仅保证协议通道合法 |
| 摇杆回中及拨杆顺序转换 | 命令业务状态条件，防止模式切换时沿用满杆请求 | 无，设备层不维护业务操作顺序 |
| 模块单发恢复时要求回中 | 反馈丢失或命令缺失后的运动恢复条件；即使命令层仍就绪，也必须重新捕获和回中 | 无，命令层不感知拨弹反馈恢复 |
| 输出轴角度误差 ≤0.5°、速度绝对值 ≤1 rpm、连续20 ms | 本发完成的业务状态条件，不用于重复校验反馈合法性 | 无，驱动不判定本发完成 |
| 启动间隔 ≥1/feed_hz | 逐发业务节拍，未增加 config.feed_hz 的下游有效性校验 | 配置有效性仍只在 Init/Control 入口 |
| 执行时间 ≥1 s 且未完成 | 实际卡住或动作未完成时锁存故障，不再追加目标 | 无，帧新鲜只能证明通信，不能证明动作完成 |
| 命令阶段 default 提前返回 false | 非法业务阶段进入默认离线输出 | 无，业务上下文独占且只在命令层解释 |
| 单发更新后非 RUNNING 提前返回 | 超时或非法单发阶段已转故障，阻止随后继续执行 PID；唯一输出闸门仍负责归零 | 新增单发阶段可在此处转故障，入口检查无法覆盖后续转换 |

删除的检查：原 feeder_fire_mode 在线调试枚举范围检查、feeder_angle_target_deg 有限值检查，因为二者改为观测而不再作为控制输入；原分散的可选命令判空合并为入口一次。保留配置入口校验、实测周期、反馈帧龄与回绕、计算链出口有限值和唯一输出闸门

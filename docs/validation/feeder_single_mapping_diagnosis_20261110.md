# 单发操作映射只读诊断

日期：2026-11-10

用户反馈：开启摩擦轮后，右摇杆向下拨表现为连发，没有观察到单次拨弹盘转动

## 源码与复现证据

- `User/module/cmd.c`：右拨杆下位只使能运行；必须在下位后观测到左拨杆从非上位切到上位，才进入单发等待回中
- 左拨杆原先已在上位时，右拨杆切下位后保持连发选择；右摇杆回中后，正负方向均按连续速度请求处理
- 单发请求使用 `ratio <= -0.95`，源码注释约定对应向上端部；本轮未测量物理摇杆方向与通道符号的对应关系
- `User/module/feeder.c`：单发为固定一齿目标，执行期间不追加；到位且间隔满足后，持续请求会启动下一齿，因此长推允许连续逐齿进给
- 短推释放会取消后续请求，模块继续完成当前齿；当前行为不等于每次摇杆动作只允许一齿

主机编译直接使用真实 `cmd.c`、`user_math.c` 及正式业务头文件，仅以正式 `can.h` 中提取的 `BSP_CAN_t` 枚举隔离 HAL 依赖，没有新增或修改生产结构体

GCC 参数：`-std=gnu11 -fgnu89-inline -O0 -g -Wall -Wextra -Werror`，编译退出码 0；以下 6 类断言运行退出码 0

1. 左拨杆预先上位，右拨杆下位、回中后输入 +660：连发模式、倍率 +1、无单发请求
2. 右拨杆保持下位，左拨杆中位切上位并保持摇杆回中：单发就绪
3. 单发就绪输入 +660：不触发单发
4. 单发就绪输入 -660 并重复解析 100 次：持续输出单发请求，不是一次边沿事件
5. 摇杆回中：取消后续请求
6. 遥控离线：输出离线档并取消拨杆顺序记忆

临时测试源码、替身头文件和可执行程序位于 `TemporaryDirectory`，运行结束已自动清理

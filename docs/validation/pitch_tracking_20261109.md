## 已观察到的事实

- gimbal.mode=ANGLE，gimbal.pitch.state=RUNNING，config_valid=true，imu_state=READY，pitch.enabled=true，反馈角度有效且 angle_lost_count=0
- gimbal_debug_enabled=false，pitch 命令 source=INCREMENT，遥控任务每周期写入命令；在这种情况下写 gimbal_command.pitch.angle_deg 不参与增量控制，写 gimbal.pitch.target_angle_deg 也不是稳定的绝对目标命令入口
- 实际 RAM 速度环 p=0.6、i=0.177、i_limit=1，外环 p=15、i=0、out_limit=1 rad/s，最终电流上限 1 A；RAM 中 p 与 config.c 默认 0.06 不同，不能拿默认值代替现场值
- pitch 机械零点为 238.93068°，实际 RAM 机械范围为 [-20°,20°]，当前 config.c 上方说明仍写 [-30°,30°]，注释与数值不一致；本次遵守 config.c 禁改规则，仅记录

第一段 60 点、15.821 秒记录中，目标姿态固定 18.30890°，实测姿态为 19.83887°～19.91865°，平均误差约 -1.56956°；机械角为 21.44533°～21.48924°，电机几乎停滞。目标速度约 -0.41099 rad/s，软件电流为 -0.44159～-0.40460 A，平均 -0.42306 A，速度积分状态始终为 -0.99999988

该区间机械角超过 +20°，但电流指向机械行程内部，Gimbal_RunAxis 的最终限位条件不会把这条负向电流清零，不能把该区间归为软件限位禁止回程

代码中 i_limit 约束的是误差积分本身，单位 rad/s·s，不是积分输出电流。上述积分项约为 -1×0.177=-0.177 A，比例项约为 0.6×(-0.411)=-0.247 A，与总输出约 -0.423 A 相符；积分已到上限，无法持续增加以消除这段静止误差

后续用户继续移动摇杆，两段 30 点记录分别跨越约 10.687 秒和 9.905 秒，机械角分别覆盖 [-22.67578°,24.03807°] 与 [-21.44533°,23.64259°]，电机反馈转速分别覆盖 [-19,40] rpm 和 [-32,19] rpm；这证明电机有实际运动，不能结论为一直无法出力

电流发送聚合状态 gimbal_output_status=0，两轴注册成功。CAN2 管理器中第 0 个注册电机参数为 CAN2、0x20A、GM6020、reverse=false、gear=false，确认该指针对应 pitch。某次读取软件输出约 +0.05334 A，反馈电流约 +0.05383 A，CAN2 GM6020 缓存码为 +285；运动期间还读到 -5461 的缓存码，对应 -1 A。此证据支持电流命令在执行，但独立读取不用于断言逐周期精确一致性

首次变量读取遇到 PROBE_BUSY，查询采样状态后只重试一次即成功。最初尝试 motors[5] 返回 LIVE_NULL_POINTER，源码核对管理器按注册顺序存放，改读 motors[0] 并核对参数后才引用其反馈，未绕过类型解析

## 判断与后续验证

1. 若用户所说目标来自 EmberProbe 手写 angle_deg，当前命令来源不满足固定角度测试条件，必须先按既有手动命令说明选择正确来源；本次没有代替用户改写使能和目标
2. 已实测到运行中带非零回程电流的停滞，且速度积分到上限，支持重力负载、静摩擦或局部机构约束所需电流大于当时控制器可提供电流的假设；尚不能区分具体机械来源或仅凭该段确定补偿参数
3. 没有发现该停滞区间由失联撤驱、未使能或最终限位清零导致；这不等于其他时段没有这些情况
4. 建议以当前姿态附近的小固定角度目标作对照，同步记录目标、姿态、机械角、真实反馈电流和积分；正反向及不同 pitch 角度重复，分离重力偏置与摩擦阈值，再确定重力前馈、积分上限和速度增益。当前不能直接建议放宽最终 1 A 电流边界

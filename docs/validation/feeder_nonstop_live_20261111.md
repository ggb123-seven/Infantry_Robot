# 五连发不停的现场只读复现

日期：2026-11-11

## 结论

已捕获下位不停转的过程：当前单角度环未达到逐齿停稳条件，角度反馈资格频繁失效、恢复，未完成组被反复重新计五发，无法到达组完成撤驱阶段

上一轮 52512 条主机断言使用合成逐齿到位反馈验证软件计数和完成锁存，没有验证当前 PID、电流边界和机构动力学能否实际停稳，不能代表现场问题已解决

EmberProbe 读取返回 firmwareConsistency=match，选中和烧录记录的 ELF SHA-256 均为 `b78018ff2e33d1518b583eb0cd4b039a53b36ddd6736710eb1b7536dda488491`，烧录记录为 `2026-11-11T06:39:47.820Z`

用户明确表示方便复现并手动操作拨杆；本轮仅 config_get、variables_read 和有限次 variables_sample，没有写 RAM、切换环路、修改参数、复位或烧录。读取使用临时探针连接，结束即释放，不更改持续侧栏采样配置

第一窗口 120 点均为右拨杆上位、FEEDER_RELAX、阶段待命，没有捕获异常，不用于分析运行故障

当前板上为 fire_mode=2、角度环开、速度环关。RAM 配置读到 tooth_count=8、feed_hz=20、direction=-1、max_speed_rpm=300、max_current_a=10；位置 P=15、I=0、D≈0.005

## 控制与反馈路径

1. Feeder_UpdateSingle 要求每齿误差绝对值不超过 0.5°、速度绝对值不超过 1 rpm，持续 20 ms，才推进下一齿
2. 当前纯角度环输出直接为电流 A，不经过速度 PID；max_speed_rpm=300 在此模式不构成实际转速闭环限制
3. 静止时 45° 位置误差的 P 项为约 11.78 A，受模块快照量程限制后请求 10 A；在反馈约 577 rpm 时 D=0.005 对应的速度阻尼量约 0.30 A。该量纲计算解释当前为何易饱和，不单独作为电机模型或稳定性证明
4. 角度无效或超时导致 OFFLINE，反馈恢复回 RUNNING 时捕获当前位置，按用户确认的策略重新建立五发预算，因此不断落回“第一齿执行、剩余四齿”
5. 驱动将可疑转子编码器单帧增量阈值设为 8192×9/20 计数，约 0.45 转。按名义 2 ms 处理周期和 36:1 减速比折算，约 375 输出轴 rpm 即达到该阈值；实际诊断仍取决于真实逐帧间隔，不能仅凭此数值认定每一帧为何无效

250 个样本中无效反馈仍伴随有限速度，结合入口超时会把速度置 NaN 的实现，支持角度连续性检查参与撤驱，而非仅仅源时间超时。多字段非原子性限制仍适用

## 停机后的驱动核对

用户回上位后读取确认 sw_r=1、state=FEEDER_RELAX，最后一次转速读取为 0 rpm

通过 DWARF 路径确认 CAN2 管理器有四个电机，motors[0] 为 GM6020 ID0x20A，motors[1]/[2] 为 M3508 ID0x205/0x206，motors[3] 为 M2006 ID0x207、reverse=true、gear=true。未按逻辑 ID 直接猜测管理器内部数组索引

M2006 角度丢失累计读数为 39357，当前静止时 angle_valid=1。没有采集本窗口开始时的累计值，39357 不能全归因于本次 20 秒复现

## 源码核对与判断边界

1. BSP 按 CAN 总线和完整 CAN ID 分别注册容量为 1 的最新值邮箱；现场节点分别为 CAN2 / 0x20A 和 CAN2 / 0x209
2. 云台反馈只有通信任务消费，未发现另一路业务重复读取或清空 0x20A 邮箱
3. 接收路由到 BSP 邮箱后，设备层仅接受八字节标准数据帧，随后更新设备反馈时间戳；通信任务再发布到独立云台反馈邮箱
4. 当前代码在运行中机械反馈失效时使单轴进入 FAULT；任务发现任一轴故障后生成 RELAX 命令并撤销两轴遥控使能，与历史现象吻合
5. BSP 仅启用接收消息和发送完成通知，没有启用 FIFO 溢出及 CAN 总线错误通知；HAL 错误处理又按通知使能位判断，故 `hcan2.ErrorCode=0` 不能排除总线错误和 FIFO 溢出
6. BSP 的接收入队最终失败没有计数，设备层无新帧与帧格式非法都可能返回通用错误，通信任务没有保留单轴更新与发布失败原因

现有证据将故障缩小到 pitch 有效反馈链，但不足以区分电机/线束/供电中断、硬件 FIFO 丢帧、BSP 入队失败、帧格式拒绝和模块邮箱交付失败。yaw 与 INS 持续推进不支持整个系统长时间停调度的解释，但不能排除短时中断延迟或局部队列问题

# 二维云台接入 DR16 控制

日期：2026-10-26

用户确认在既有 `Task_Runtime_t.msgq` 增加 `dr16_gimbal_state`，沿用 `DR16_State_t`，不新增消息结构体

## 输入和状态

| 输入 | 行为 |
| --- | --- |
| 右拨杆中位 | 两轴 RELAX、零电流，确认下一次上位使能 |
| 右拨杆上位 | 中位确认后进入 ANGLE，首次进入捕获当前姿态，避免跳向旧目标 |
| 右拨杆下位或非法位置 | 两轴 RELAX，重新开启前先回中位 |
| 右摇杆左右 | 按实际周期累加 yaw 目标角，满杆 60°/s |
| 右摇杆上下 | 按实际周期累加 pitch 目标角，满杆 60°/s |
| 右摇杆回中 | 5% 中心死区内不改变目标角，继续惯性稳向 |
| 遥控失联、帧龄超过 100 ms、时间回退、读邮箱错误 | 两轴 RELAX，恢复后先回中位再拨上，不自动重新出力 |
| 模块故障或输出邮箱发布失败 | 撤销遥控使能，重新使能前先回中位 |

输入状态为 WAIT_MIDDLE、READY、ACTIVE，启动默认 WAIT_MIDDLE，非法状态回 WAIT_MIDDLE

右摇杆两通道初始均以负号映射到当前 INS 角度坐标，方向常量集中在 `motor_gimbal.c` 顶部；物理左右、抬头方向尚未实测，需在低速条件下核对

遥控只选择模式和组装目标，闭环、反馈有效性、机械限位和 PID 仍由原 Gimbal 模块处理。目标积分使用模块上周期实际限幅后的目标，避免持续推向 pitch 边界时积累不可达目标。编码器机械限位、两环参数及电流上限沿用现有配置

## 消息流和修改范围

```text
UART -> DR16 任务 -> dr16_state 邮箱 -> 底盘任务
                 -> dr16_gimbal_state 独立邮箱 -> 云台任务输入状态机
                   -> Gimbal_Control -> gimbal_output -> CAN 任务
```

- 两个遥控邮箱各保留同一源时间的完整最新快照，一路重置或写入失败不阻断另一路发布
- 新邮箱由 Task_Init 统一创建、检查和回收，新增创建失败枚举追加在末尾，保留旧诊断值
- 每周期覆盖 `gimbal_command.mode` 和前馈，调试器直接写命令不再作为使能入口
- 正弦测试默认关闭；主动打开后覆盖 yaw 目标，同样受遥控停机约束
- 同步修正云台任务非法节拍时除零和零延时风险，初始化失败持续零输出
- 源码只改 `User/task` 的 `user_task.h`、`init.c`、`dr16_task.c`、`motor_gimbal.c/.h`
- 工作树原有 `User/module/config.c` 改动及文档删除不纳入本次提交

## 人工评审和实测边界

- 未改 main、CubeMX、BSP、设备协议及模块源码，硬件资源门禁通过
- 遥控缓存和输入状态仅由云台任务拥有，消息队列复制完整数据，无新增 ISR 共享状态或临界区
- 新邮箱创建、读取、重置、写入和清理均检查结果；无输入和非法分支默认 RELAX
- ARM 静态栈报告 `Task_motor_gimbal` 为 224 B，不能替代 FreeRTOS 栈高水位实测
- 本轮未烧录、未运行真实电机、未执行 Keil 编译；CMake 构建使用当前工作树，包括用户既有配置参数
- 上板先右拨杆中位确认零电流，再上位确认捕获当前姿态；低幅验证右摇杆左右和抬头方向、回中保持、pitch 限位、关遥控停机及恢复回中后使能
- 100 ms 为源帧龄软件阈值，实际停机时延还受任务调度和 CAN 发送周期影响，未作实机量测
- 启用 ANGLE 后转动底座仍会触发惯性补偿，搬动云台前先回中位；本轮未增加离地识别

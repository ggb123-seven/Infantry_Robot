# 拿起二维云台后 yaw 高速旋转：数据分析与修改规划

> 本文保留分析阶段的证据与规划；用户随后确认开始修改，已实施的机械运动保护及验证边界见 `2026-10-27_yaw_motion_protection.md`

## 本轮结论

已经确认控制链存在的缺口：惯性闭环持续要求纠正姿态时，yaw 编码器已经高速旋转，但编码器转速没有参与速度制动或超速状态转换，速度环仍按 IMU Z 角速度计算电流。手持后若 IMU 所在上部被手限制、底座可以自由转动，电机可以带动底座反转，而 IMU 保持近似静止；此时控制器持续出力，无法通过当前反馈判断机械端已经高速旋转。

本轮记录强烈符合这种机械约束变化。尚未确认用户具体拿住部位，不能仅凭单个上部 IMU 区分底座反转、IMU 安装松动或其他机械脱耦。已确认的软件缺口不依赖这项现场判断。后续需对照“托住底座”和“拿住上部”采集，确认实际反转的部件。

积分残留及持续姿态误差放大了现象。仅减小角速度目标上限或关闭 Ki 都不能保证消除机械端持续转动：异常期间的惯性角速度目标本身不高，比例项也能继续施加电流。

本轮只分析 CSV、读取源码及生成报告和图表，没有修改控制源码、PID 配置或 MCU，也没有执行烧录、复位或调试采样控制。

## 峰值现场与积分放大

第二段峰值位于 CSV 第 541 行，北京时间 12:15:59.152，即第 13.665 s：

| 变量 | 值 | 含义 |
| --- | --- | --- |
| `gimbal.yaw.motor_speed_rad_s` | 36.966 rad/s，约 353 rpm | 电机相对底座的机械转速 |
| `gimbal.yaw.speed_rad_s` | 0.0142 rad/s | 控制器采用的 IMU Z 角速度 |
| `gimbal.yaw.target_speed_rad_s` | 1.973 rad/s，约 18.84 rpm | 惯性速度目标 |
| `gimbal.yaw.angle_deg` | -6.872° | 上部惯性 yaw 姿态 |
| `gimbal.yaw.target_angle_deg` | 0.660° | 目标姿态 |
| `gimbal.yaw.output_current_a` | 0.500 A | 模块电流指令，已达到上限 |
| `gimbal.yaw.speed_pid.i` | 2.42247 | 保存的速度误差积分 |
| 速度环 Ki × 已保存积分 | 0.42878 A | 积分贡献的主体电流 |

约 7.53° 的姿态误差经外环 Kp=15 换算为约 1.97 rad/s 的修正速度。由于 IMU 读数接近零，速度环继续认为速度不足；即使编码器已经达到 353 rpm，当前计算也不会使用这个机械速度减小电流。

在第 13.1～16.8 s，机械转速中位数为 35.5 rad/s（约 339 rpm），IMU Z 角速度中位数约 -0.004 rad/s，目标速度中位数约 1.94 rad/s，电流中位数为 0.5 A。已保存积分贡献约 0.429 A，比例项估算中位数约 0.117 A，合成后持续饱和。

`PID_Calc()` 已有饱和时不继续保存新增积分的逻辑；本例饱和后积分大部分保持在 2.42247，不能表述为“积分无限增长”。实际问题是此前积累的正积分持续保留，加上仍存在的比例输出，而编码器高速状态没有进入保护。字段分次读取，电流重构仅用于解释持续趋势，不能当作严格逐控制周期等式。

第一段也可看到目标速度已经变为负值而输出电流仍为正值。例如第 5.975 s，机械速度约 33.82 rad/s，IMU 约 -0.125 rad/s，目标约 -0.168 rad/s，电流仍约 +0.100 A。保存积分能使电机在微小反向速度误差下继续同向出力。

## 与源码对应

1. `User/module/gimbal.c` 的 `Gimbal_UpdateImu()` 将累计 yaw 写入 `yaw.angle_deg`，将 IMU Z 分量写入 `yaw.speed_rad_s`
2. `Gimbal_UpdateAxisFeedback()` 将 CAN 电机 rpm 换算到 `motor_speed_rad_s`，机械连续角与 IMU 惯性角分别保存
3. `Gimbal_RunAxis()` 的角度外环输出惯性速度目标；速度内环使用 `axis->speed_rad_s`，没有使用机械转速进行制动
4. `motor_speed_rad_s` 在运行路径仅要求为有限值，没有与机械安全转速比较，也没有高速持续时间或“出力但惯性响应不足”的保护
5. `max_speed_rad_s` 约 33.51 rad/s，只夹住速度目标，不约束测得的电机转速；yaw 机械行程保护关闭
6. `User/component/pid.c` 在允许范围内积累误差，饱和后阻止新增积分保存，但不会因编码器高速而撤销已有积分
7. `User/task/motor_gimbal.c` 每周期先暂设命令为 RELAX，再按遥控状态填入运行命令；内部命令变量的瞬时 RELAX 不等同于实际轴停止

## 当前证据不支持的归因

- **摇杆连续给旋转命令**：记录中 yaw 命令目标始终为 0.659694°，命令角速度前馈始终为零；实际 `gimbal.mode` 全部为 ANGLE，两轴状态全部为 RUNNING
- **累计 yaw 跳过整圈**：机械端累计数十圈时，INS yaw 仍在约 -13.35°～11.98°之间；没有同量级惯性角跳变
- **接近欧拉奇异点**：Pitch 约 14.86°～20.31°，Roll 约 -6.62°～10.84°，远离 ±90°；机体系 Z 与 yaw 导数的坐标差不能直接解释该时段上千倍的转速差
- **已确认 IMU 故障**：源时间戳和 INS 更新计数在每个观测点推进，四元数模约 0.999965～1.000029，模块采用的 IMU 快照一直有效；这些证据不支持直接判定 IMU 失效，但也不能排除安装松动或真实机械脱耦
- **本轮触发 CAN 离线保护**：采样点的两轴状态始终为 RUNNING，反馈源时间戳持续推进，未观察到 OFFLINE；约 25 ms 的观测不能排除更短暂的事件

`INS.state.valid` 有 292 条为零，但 `INS_Update()` 每周期入口先清零、成功末尾再置一，因此异步调试读取会捕获更新中的零值。配合模块状态、计数推进及已发布快照持续有效，不能把这些零值直接计为 292 次 IMU 故障。类似地，命令 mode 的 5 条零值也不能直接计为停机。

同一 CSV 行中，`gimbal.imu.sample_time_us` 比 yaw 电机反馈源时间晚约 2.014～4.082 ms，已经证明这些字段不是同一瞬间的原子快照。持续数秒的现象可靠，毫秒级先后与单周期返回值需另做同步观测。

## 修改规划：按可验收步骤推进

### 第一步：补齐现场操作对照

保持当前参数记录基线，标记每次拿起、放下、拿住部位、是否主动转底座。至少区分托住 yaw 底座与拿住上部两种约束；出现明显加速及时切回现有中位停机，不需要维持数秒高速来增加样本。

优先采集以下字段，避免全结构体读取影响关键变量的时序：两轴状态、实际模式、yaw 机械角与机械速度、yaw 惯性角与角速度、目标角与目标速度、命令前馈、输出电流、两环积分及误差、电机与 IMU 源时间、Roll/Pitch 和三轴陀螺仪。记录操作者拿住的部位，因为现有传感器无法直接观测这一条件。

### 第二步：在模块内加入机械端安全约束

在 `User/module/gimbal.c` 负责统一判断，任务只传递命令、周期及反馈。用真实编码器转速触发保护，不能继续只限制惯性速度目标。先以独立于工作目标的机械绝对超速门槛兜底，再按正常底座最大运动速度、遥控最大运动速度及实测波动确定阈值。

保护优先于正常姿态计算；触发时撤销驱动电流、清空两环历史并锁存故障，复用现有中位确认流程重新使能。禁止速度刚下降就自动恢复原目标，否则拿住上部时会反复加速。现有 OFFLINE 自动恢复语义保留，超速故障不得归入 OFFLINE。

零电流表示撤销驱动，转子仍会因惯性滑行；如需要明确的停转时间，应另行验证基于编码器的受限主动阻尼和电流方向，不能把零电流写成“立即停止”。

机械转速门槛与必要的持续时间应覆盖正常底座反向运动场景。单个上部 IMU 无法区分用户拿起与底盘快速转动，超速保护也不能单靠“IMU 小、编码器大”判断传感器坏了。最终参数在新采集数据对比后确认，不把分析用的 5 rad/s 直接写入固件。

### 第三步：处理不可达姿态与积分释放

在机械端安全约束之外，评估“持续出力、机械端明显转动、惯性姿态未按要求变化”的响应不足保护。进入保护后清除已有速度积分；若采用积分冻结或泄漏，仍需验证比例项不会继续驱动空载机械端加速。不能只把 Ki 置零当作完成修复。

正常稳向仍可使用 IMU，但机械端速度约束必须独立保留。若希望拿起即完全不施力，需要明确的搬运/停机命令或可验证的拿起检测；仅凭现有单个上部 IMU 和电机编码器不能保证无歧义自动识别所有拿起动作。当前可以使用现有中位作为手持停机入口，后续再决定是否增加模式。

本轮不定稿新增结构体。实施若需要增加配置或运行时字段，先按根目录协作规则与用户讨论名称、字段和兼容性；同时取得 `User/module` 源码修改范围的明确授权。

### 第四步：软件回归与实物验收

- 主机回放构造本轮的关键条件：惯性速度约 0、姿态误差约 7.5°、机械速度逐步升至约 37 rad/s；检查保护触发、零输出、积分清除和故障锁存
- 覆盖阈值上下边界、持续时间、短脉冲、正反方向、非法速度、反馈超时、恢复后中位重新使能及另一轴行为
- 用正常快速转底座数据验证不会把允许的稳向补偿误停为故障
- 完成 ARM 编译、ARCH/HW/SPEC 和源码规则复核后再进入上板；编译不能替代停机时延和实际机械速度测量
- 实物验收分别覆盖托底座、拿上部、放回、快速扰动、持续偏离目标及中位停机，量测峰值机械速度、撤销输出时延和滑行时间
- 若目标包含搬运状态完全不主动转动，验收应增加“进入搬运/停机状态后持续零驱动”和重新使能时捕获当前姿态

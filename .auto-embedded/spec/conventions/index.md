# 编码与协作约定 spec（conventions）

> 本层是"怎么写才安全"的可执行约定。EXECUTE/REVIEW 必读。

## 证据优先（铁律）

没有以下任一证据，**禁止**宣称"已修好/应该没问题"：
代码位置 · 编译输出 · 测试结果 · 串口日志 · 数据手册依据 · 网表依据 · 实测波形/寄存器状态。
完成声明必须在当前回复内附"命令 + 输出 + 与验证标准的对照"。

## 复用优先

本地离线索引 → 官方文档/Context7 → 开源驱动 → 最后才自己写。不凭记忆猜接口。

## 代码规范

- 模块化：`.c` + `.h` 成对；公共 API 走 `.h`，内部函数 `static`。
- 命名前缀按层（halport_/bsp_/drv_/mw_/svc_/app_）。
- `volatile`：ISR 与主循环共享变量、MMIO 必须 `volatile`；不滥用。
- 临界区：多字节共享状态读写用临界区/原子；Cortex-M0+ 无 LDREX 注意。
- ISR 纪律：ISR 体 ≤ 20 行，只置标志/搬数据，重活交主循环；ISR 内禁 `printf`/阻塞/动态内存。
- 魔数写回注释来源（`@datasheet p.XX` / `@netlist`）。
- 项目自研代码中的每个实际处理阶段都要在代码前写简体中文目的注释，例如初始化、数据获取、校验、计算、发布和故障处理；注释说明阶段目的，不逐行翻译赋值、判断或显而易见的调用。
- `while` 循环内的函数调用必须由调用前的中文目的注释覆盖；相邻调用属于同一处理阶段时允许共用一条阶段注释。
- 花括号换行规则优先于 120 列单行规则，不得为了压缩控制块而破坏花括号格式。
- 函数、条件分支、循环、`switch`、结构体、联合体、枚举和多行初始化的左花括号 `{` 必须另起一行，右花括号 `}` 必须独占一行并与对应语句对齐。
- 禁止使用 `} else {` 和 `} else if (...) {`；右花括号、`else`/`else if` 和下一层左花括号必须分别独占一行。
- 声明、赋值、函数调用、`return` 和短条件在不超过 120 列时保持单行；禁止使用格式化工具制造无意义换行，工具运行后必须人工收回可单行表达的机械拆分。

## 编码后强制检查

每完成一个源码文件或一个独立实现改动点，必须立即执行以下检查，全部通过后才能继续下一个改动点：

1. 重新读取根目录 `AGENTS.md` 和 `agent.md`，确认授权、分层、注释和排版要求。
2. 扫描同行左花括号、`} else {`/`} else if`、缺失的控制块花括号、超过 120 列、行尾空白和可单行却被机械拆分的语句。
3. 人工核对每个处理阶段的中文目的注释，删除逐行翻译式无效注释，并核对 Doxygen 参数、返回值和结构体集中说明。
4. 检查依赖方向、错误返回、RTOS/HAL 创建结果、ISR 共享状态、临界区和默认输出安全性。
5. 修正全部发现后重新执行检查；每个实施清单项还必须运行对应编译、静态检查和测试，并保存验证证据。

## Git 快照

每完成一个独立实现步骤 → 代码复核、对应编译和测试通过并记录证据 → 本地 `git add <具体文件>` 或相关差异块（**不用 -A**）→ commit → 下一步；用户已授权此流程，无需逐次确认；
**绝不自动 push**。敏感文件（.env/.key/.pem/*secret*/*token*/id_rsa*）暂停存档。

## 沉淀（promote 回流）
> REVIEW 阶段把每次的设计决策/约定/坑/gotcha 沉淀于此，下次自动注入。
- [约定] Keil ARMCC 工程使用 FreeRTOS V10.3.1 时，必须包含 portable/RVDS/ARM_CM4F/port.c 与 portmacro.h，并将实际启用的外设初始化源文件、HAL 驱动源文件和 HAL 时基源文件纳入 .uvprojx。
- [约定] VS Code 的 STM32Cube J-Link 调试出现 JLinkGDBServerCL 被 SIGTERM 终止时，该行通常是调试适配器失败后的清理结果；应先检查此前的 GDB Remote 握手错误。若 RTOS 代理链路不稳定，可在 launch.json 中显式设置 serverRtos.enabled=false，使 GDB 直连 J-Link GDB Server。
- [坑/gotcha] RoboMaster RM 电机参数中的 id 使用反馈 CAN ID（0x200 + 电调 ID）；C620 电调 ID 1 应填 0x201，而不是 1。MOTOR_RM_SetOutput、MOTOR_RM_SetTorqueCurrent 和 MOTOR_RM_Relax 只更新发送缓存，随后必须调用 MOTOR_RM_FlushGroup 或 MOTOR_RM_FlushCAN 才会真正下发。
- [约定] RoboMaster C620/M3508 首次接入时，由唯一底盘任务拥有 0x200 控制帧发送权；上电默认持续发送零电流，先确认 0x201~0x208 反馈、物理 ID 和安装方向，再通过明确使能条件开放非零输出。
- [坑/gotcha] J-Link 调试现象与源码不一致时，先比较目标 Flash 0x08000000 的初始 MSP/Reset 向量和待调试 ELF 的 .isr_vector；VS Code 的自动二进制选择可能下载旧 AXF/ELF，应将 imageFileName 与 symbolFileName 显式固定到当前 CMake 产物。
- [可复用模式] CMake 工具链文件先查当前环境，再查显式根目录和 STM32Cube Bundle；同一工具链的 gcc、g++、objcopy 与 size 必须来自同一 bin 目录。
- [坑/gotcha] Windows PowerShell 5 会把无 BOM 的 UTF-8 脚本按系统代码页读取；含中文的兼容脚本必须保存为 UTF-8 BOM，并避免依赖新版 .NET API。
- [可复用模式] RoboMaster M3508/C620 速度闭环中，PID 输入统一使用减速箱输出轴 rpm，PID 输出统一使用转子侧电流指令 A；MOTOR_RM_SetTorqueCurrent 只是电流指令换算与缓存接口，不得描述为软件电流环。
- [可复用模式] EmberProbe 在线调参参数应放在具名 volatile RAM 结构体中，并保留集中字段注释、单位和非法值处理；控制任务每周期先复制并校验调参快照，再同步到算法参数，禁止调试器直接修改算法内部状态。
- [约定] 跨周期控制状态集中到 module 主结构体并标明单位；task 只保留设备实例和最终输出等 I/O 编排变量，只在当前语句使用且没有日志、反馈、重试消费者的中间状态不额外封装。
- [约定] 任务文件优先展示公共任务入口和 while 主流程；static 私有函数在入口前只写前置声明，完整实现统一放到任务函数之后，便于先读业务编排再按需下钻细节。
- [约定] 项目默认单行宽度为 120 列；简单变量声明、赋值、函数调用、return 和短条件判断不超过 120 列时必须保持单行，禁止在赋值运算符后或可单行容纳的短参数列表中机械换行；只有超出行宽或包含多个独立逻辑分组时才按参数或逻辑分组换行。
- [约定] 花括号规则优先于 120 列单行规则；函数、条件分支、循环、switch、结构体、联合体、枚举和多行初始化的左花括号必须另起一行，右花括号必须独占一行并对齐，禁止使用右花括号、else 与左花括号同处一行的写法。
- [约定] 控制对象命名必须与闭环范围一致：单个电机的速度 PID 应描述为单电机速度环；只有包含底盘运动学、车体速度反馈或多电机协调时才能描述为底盘速度环。
- [可复用模式] 电机间歇启停的 EmberProbe 诊断结构体应在同一具名 volatile RAM 全局量中同时提供目标/实际转速、误差、电流指令、PID 积分、在线状态、反馈年龄、反馈更新结果和 CAN 发送结果；调试器可修改的目标与 PID 参数由任务每周期复制为局部快照后再传入算法，禁止直接修改算法内部状态。
- [约定] 供 EmberProbe 展开的全局监视结构体应在 designated initializer 中显式列出关键调参和观测字段；实时反馈字段先初始化为 0，再由所属任务按控制周期持续刷新。
- [坑/gotcha] 自动格式化器的默认列宽可能把本可在 120 列内表达的短赋值和函数调用机械拆行；提交前必须复核并收回单行，不能以工具输出替代项目排版规则。
- [坑/gotcha] clang-format 的 Allman 配置不会自动把 C 结构体初始化和复合字面量的左花括号移到下一行；格式化后必须额外扫描同一行左花括号并手工修正。
- [约定] 速度闭环接入二阶低通时，反馈滤波器应以当前反馈预置、输出滤波器应以零输出预置；截止频率小于等于 0 时使用直通系数，启用滤波时必须小于采样频率的一半。
- [约定] 同一 CAN 上的 M3508/C620 ID 1~4 共用 0x200 控制帧；控制任务必须先为四个电机分别写入电流缓存，再调用一次 MOTOR_RM_FlushGroup() 统一组帧，禁止逐电机调用 MOTOR_RM_Ctrl() 造成同周期多帧和半更新数据。
- [约定] EmberProbe 暂停会立即停住 MCU，固件无法在暂停瞬间补发零电流；电机调试必须先关闭控制使能，等待连续零电流帧确认停机就绪后再暂停。
- [可复用模式] CAN 等周期状态反馈使用容量为 1 的最新值邮箱：队列满时先移除旧帧再写入新帧；要求顺序和不可丢失的事件继续使用普通保序队列。
- [坑/gotcha] 使用 LwRB 承载固定长度消息时，底层存储区必须按容量乘以消息大小后额外增加 1 字节；入队和出队必须分别使用 LWRB_FLAG_WRITE_ALL 与 LWRB_FLAG_READ_ALL，禁止接受部分消息。
- [约定] 任务专用主机测试在记录验证结果后必须清理测试源码和可执行文件，正式回归测试资产不得删除
- [可复用模式] 从共用 CAN 驱动移除某类电机时，必须核对共享反馈 ID 与控制帧槽位，不能按型号名称整段删除共享协议；应以相同输入对比保留型号的组帧字节、反馈标度及安全归零路径
- [约定] EmberProbe Skills 可作为项目工具资产纳入版本控制；.agents/skills/_emberprobe/agent-bridge.json 是含用户级绝对路径的本机桥接指针，必须由 .gitignore 排除
- [约定] BMI088 初始化按参考工程执行阻塞式静止校准：连续采样 6000 次，以加速度模长和三轴角速度极差检测运动并整轮重采，10 秒超时后使用参考工程默认机号标定值；正常读取应用 AccelScale 并扣除三轴 GyroOffset
- [约定] BMI088 加速度计与陀螺仪融合无法提供绝对航向观测，当前 Quaternion EKF 固定 GyroBias[2]=0，Yaw 与 YawTotalAngle 会累计 Z 轴零偏；EmberProbe 直接读取 1 kHz 更新中的 INS 结构体会产生跨字段非一致快照，验证姿态曲线应使用带序号的一致性快照或消息发布接口
- [约定] INS 公开姿态统一按右手定则命名：Roll 为绕 X 轴横滚，Pitch 为绕 Y 轴俯仰，Yaw 为绕 Z 轴偏航，单位度；算法迁移须用已知正反单轴及组合姿态验证字段映射，禁止沿用旧版 Roll/Pitch 互换约定
- [坑/gotcha] IMU 实测须将供电异常、温度过渡及更新计数重新起算的记录分段分析；动作段不得用于静止漂移统计，缺少外部角度基准或不同参数对照时不得宣称绝对精度或最佳参数
- [设计决策] GM6020 yaw 速度环在 module 层将驱动 rpm 反馈换算为 rad/s，PID 输出单位为转子侧电流 A；task 只负责调度，CAN 命令统一交给通信任务发送。全局调试区的字段单位以集中说明为准，保留旧字段名时必须注明真实单位。
- [约定] GM6020 ID5/ID6 在 CAN2 使用反馈 0x209/0x20A 与共用电流控制帧 0x2FE；具名缓存通过联合体别名复用原输出槽位，不能增加帧长度。两个反馈邮箱只发布完整标准数据新帧，消费者按微秒时间戳判断时效；业务任务未接入时由通信任务持续发送零电流。
- [约定] ELF 变量直接读取遇到同名局部符号时必须按编译单元限定；裸名匹配多个符号应返回歧义候选，不得静默选择符号表中的首项
- [约定] 角度坐标范围、零点基准与环绕误差分别定义：单圈位置可用 [0,360) 度表示，最短路径误差保留正负方向并限制在半圈内；编码器原生零点不等于云台机械正前方，机械相对角需减去标定偏置后再环绕，不能用上电位置代替固定机械零点
- [坑/gotcha] EmberProbe 0.8.8 的浮点写入滑块默认上下限为 -1 与 1，独立于固件变量的单位与业务范围，角度目标需在面板手动设置上下限；actual 等周期反馈字段不应作为控制输入。采样停止时写入控件整体禁用，运行调试模式只支持对齐的 32 位写入，bool 等单字节字段需暂停调试后写入；区分控件禁用与固件周期回写，不能把写入请求值当成实际控制状态
- [约定] 云台线性角度控制必须区分 0° 与 360° 目标，编码器跨零后保持连续位置；连续反馈失效后保留机械零点，清空连续位置并停机，确认机械圈数后人工重新使能。外部角速度须由调用方保证时效、方向和参考系一致，无效时回退编码器转速
- [约定] 云台角度跟随的目标角速度前馈必须与目标角度使用同一时间和方向，解析轨迹直接求导；前馈在角度环修正量之后、速度内环之前叠加，对总速度统一限幅并协调积分饱和保护，禁用与反馈异常必须同时阻断前馈。变周期轨迹按当前实际周期推进相位，开关前馈不得重置轨迹相位
- [约定] 模块初始化实现由 module 层提供，统一装配入口 Task_InitModules 直接调用并处理失败；周期任务不额外提供只检查调度参数再转调模块的业务初始化包装函数。RTOS 节拍约束由任务装配层检查，模块只接收物理频率参数
- [设计决策] 机械零点标定配置与连续位置有效性必须分开管理：固定零点由模块提供默认值并在初始化时采纳，任务不重复写入；反馈异常清空连续位置与两环历史、停机并撤销使能，但保留已标定零点。恢复后确认机械圈数并人工重新使能，无需重复标定；单圈零点不能恢复丢失圈数，禁止自动恢复旧使能
- [设计决策] 底盘 motor_chassis_watch 的 actual_speed_rpm 和 target_speed_rpm 为四路输出轴 rpm 观测数组，下标 0~3 对应电调 ID1~4；目标取限幅和缓启动后实际进入速度环的值，任务每周期刷新，禁止作为控制输入。pid 保留在线调参，归一化轮速尺度固定为任务常量 100 rpm；volatile 不保证调试器多字段采样一致性。
- [约定] 每完成一个独立实现步骤，先完成对应复核、编译和测试并记录证据，通过后立即提交本地 Git，再继续下一步；无需重复询问提交授权，仅暂存本步骤差异，明确未执行的上板验证，不自动推送远端。
- [坑/gotcha] 实例内 PID 参数指针引用实例自身副本时，初始化后不得整体复制实例；公共 PID 参数变更须清除各轮旧积分，修改微分截止频率须同步重建滤波系数，调参当周期仍可产生新的积分增量
- [约定] 云台两轴参数同步时分别保留机械零点、限位、方向与 CAN 标识；控制参数使用独立副本。角速度反馈从编码器换为 IMU 时，必须核对安装坐标与机械轴投影、单位、跨任务快照一致性和数据时效，不得直接将机体系陀螺仪 Z 分量等同于所有姿态下的 yaw 轴角速度。
- [约定] 云台机械零点应记录 Gimbal 的 encoder_deg，即经过 reversed 方向修正后的单圈角度；修改 reversed 或电机与机构的安装关系后，必须重新核对零点，避免混用原始编码器坐标与方向修正坐标。
- [约定] 云台 min_angle_deg 与 max_angle_deg 表示相对本轴机械零点的目标角度范围，单位度；固化用户指定的范围时，应在配置集中说明中明确参考零点，并区分目标范围与实际机械行程验证结果。
- [约定] 有限行程的 pitch 以固定水平零点映射到 [-180,180) 度，首帧和失联恢复直接确定正负角；即使不使用连续角展开器，也必须校验反馈时间倒退、重复帧和超时间隔。yaw 保留连续角展开。
- [设计决策] 云台机械范围与惯性姿态目标分开：启用机械约束时按机械角加姿态目标增量夹住目标，SPEED 与前馈同样受限，边界阻断向外电流并保留向内恢复；该局部标量近似不提供制动距离保证。进入 ANGLE 时捕获当前姿态并清零前馈，IMU 用源时间独立判过期，故障回 RELAX 后等待新的有效快照即可就绪，不再要求静止。此前编码器角度闭环及 IMU 无效回退编码器的历史约定由此替代。
- [设计决策] 按用户确认移除云台额外的连续静止使能检查：有效 IMU 首帧直接由 WAITING=0 进入 READY=2，FAULT=3 保留锁存至 RELAX，解除后等待有效新帧；不再等待 1 秒静止或低变化率。继续校验源时间、数值及相邻帧连续性并保留机械保护，替代此前重新完成静止检查的约定。BMI088 初始化的原有零偏校准不受此决定影响。

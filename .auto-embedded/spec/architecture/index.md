# 分层架构 spec（architecture）

> index.md 是本层入口：开发前清单（Pre-Development Checklist）+ 质量门（Quality Check）。
> RESEARCH/PLAN 必读；派 Builder/Verifier 时按 implement/verify.jsonl 自动注入。

## 六层模型与依赖方向

| 层 | 前缀 | 职责 | 只能依赖 |
|---|---|---|---|
| L1 HAL Port | `halport_` | 厂商 HAL/寄存器的薄封装，隔离硬件差异 | 厂商头 |
| L2 BSP | `bsp_` | 板级：时钟/引脚/外设实例 | L1 |
| L3 Driver | `drv_` | 设备驱动（传感器/屏/存储） | L1/L2 |
| L4 Middleware | `mw_` | 协议/算法/文件系统 | L1~L3 |
| L5 Service | `svc_` | 业务服务（采集/控制/CLI） | L1~L4 |
| L6 App | `app_` | 编排与主循环 | L2~L5（**禁** L1 厂商头） |

依赖只能自上而下；跨硬件一律走 L1 HAL Port。

## 开发前清单（Pre-Development Checklist）

- [ ] 每个新文件标明层级 L1~L6 与命名前缀
- [ ] 应用层（app/）**不** `#include` 厂商 HAL 头（stm32*/gd32*/esp_*/ti_msp_dl_* 等）
- [ ] 应用层**不**直接裸写寄存器（`*(volatile..*)0x..`）——封装到 HAL/BSP
- [ ] 不引入 catch-all mega-header（`*_headfile.h`/`all.h`）间接拉厂商头
- [ ] `main.c` 只做启动编排与主循环调度；CubeMX/HAL/RTOS 生成的初始化与调度调用数量不限，其余自定义顶层调用 ≤ 6

## 质量门（Quality Check，REVIEW 必跑）

机械门禁（与 embedded-dev 同源思路，可外接 arch-check）：

| 编号 | 规则 |
|---|---|
| ARCH-1/1B/1C | 应用层禁厂商头 / 禁 catch-all mega-header / 禁裸 MMIO |
| ARCH-2 | main.c 自定义顶层调用 ≤ 6；`HAL_Init`、时钟配置、`MX_*_Init` 和 RTOS 内核/调度器调用不计数 |
| ARCH-3 | ISR/回调函数体 ≤ 20 行 |
| ARCH-4 | 应用层 extern 变量 = 0 |
| ARCH-5/6 | 单 .c ≤ 800 行；单 .h 公共 API ≤ 20 |
| ARCH-7/7B | mega-header 检测 / app 层引用 mega-header |
| ARCH-8 | hw-lock.yaml pin/dma/irq/timer 冲突检测 |

> 若工程已装 embedded-dev 的 `scripts/arch-check.sh`/`.ps1`，REVIEW 阶段直接跑它做门禁。

## 沉淀（promote 回流）
> 只沉淀**可复用知识**（决策/约定/坑/模式），任务过程性事实留在 tasks/ 不要 promote。下次会自动注入。
- [设计决策] ARCH-2 只统计 main 类入口的自定义顶层调用；HAL_Init、时钟配置、MX_*_Init 和 RTOS 内核/调度器调用属于生成的启动编排，不计入数量上限。
- [设计决策] 单个 M3508 电机控制按主运行与速度算法拆分：motor_chassis 拥有任务循环、电机驱动编排、在线判断和电流指令下发；motor_speed_control 只负责这一台电机的速度限幅、缓启动、PID 计算、调参和速度反馈结构体，不代表整个底盘速度闭环。
- [坑/gotcha] motor_speed_control 是单个 M3508 电机的速度算法模块，不应拥有 Task_motor_chassis 或直接调用 RM 设备驱动；现有 motor_chassis 任务入口、在线判断、反馈采集和电流指令下发必须由 motor_chassis 编排。
- [约定] motor_chassis 作为当前单电机主运行文件时直接调用现有 RM 驱动 API；仅被该任务使用的一对一 getter/setter 不再包装成公共函数，只有多调用者共享或需要统一策略时才增加封装。
- [可复用模式] RTOS 业务任务的 while 循环只保留周期推进、module/driver API 调用和等待；算法细节放入 module，实现中不为一对一设备调用增加 task 内 static 步骤函数。
- [可复用模式] 参考工程采用 task/module/component 三层：task 只负责消息或设备 I/O、调用顺序和周期调度；module 用一个主结构体集中保存 parameter/setpoint/feedback/PID/output，并提供 Init/UpdateFeedback/Control/DumpOutput 业务 API；component 只提供通用 PID、滤波等算法。禁止用 task 文件内的 static 步骤函数替代 module 边界。
- [约定] osKernelLock() 只锁定 RTOS 任务调度，不会屏蔽硬件中断；ISR 与任务共享的数据仍须按访问模型使用 volatile、原子操作、RTOS 通知或最小临界区保护，禁止把调度锁描述或使用为中断锁。
- [可复用模式] 任务层故障检测应消费 Device/Module 的公开快照并输出诊断快照，不直接访问 HAL/BSP 或设备私有对象。
- [约定] 故障检测等完整业务诊断逻辑归入 User/module；User/task 只负责周期调用、消息流和调试发布编排。
- [约定] 底盘任务只选择机械布局并组装归一化运动指令，Chassis 模块持有通用 Mixer 并在速度 PID 前统一解算，具体轮速公式集中在 Component 层
- [坑/gotcha] 移植 Madgwick 六轴姿态核心时，水平静止可能得到全零梯度，归一化前须跳过零梯度并验证四元数有限；六轴算法不能通过重力观测消除绝对航向漂移
- [坑/gotcha] 反馈时间戳为 32 位微秒计数时，任务接收新帧后必须恢复到完整单调时间基准，后续失联判定使用完整时间差；不能持续对旧反馈使用 32 位模减，否则约 71.6 分钟回绕后可能重新放行旧反馈。先按微秒检查超时边界，再转换毫秒，避免截断误差。
- [设计决策] GM6020 yaw 调试链使用独立 500 Hz 任务调用模块，电流命令邮箱只存 float 安培值；CAN 任务每周期消费一次，空邮箱归零，pitch 恒零。直接将原停机接口改为可调电流接口，传零即停机，不叠加重复封装。当前命令没有生成时间戳，不提供按生成时刻的过期校验。
- [设计决策] GM6020 偏航角度外环在 module 层复用 KPID_Params_t 和 PID，独立初始化、显式使能；对外目标角和反馈角使用度，进入 PID 前转换为 rad，角速度反馈和输出使用 rad/s，range 配置单圈或连续角度。使用外部反馈角速度作为微分；当前角度反馈使用电机编码器角度，角速度由编码器 rpm 换算；后续 INS 原始陀螺仪读数接角速度输入，INS 融合偏航角接角度输入，并统一零点、方向和角度区间。当前串级链由 Gimbal_Update 调用 Gimbal_YawRunAt，将角度输出写入速度目标，再由速度环生成电流，启停切换清空历史
- [设计决策] 云台任务只负责启动绑定与周期调度；Gimbal 模块绑定系统预先创建的反馈和 float 电流邮箱，自行读取并缓存编码器反馈、恢复完整时间戳、运行角度与速度串级控制并发布电流，发布失败时停止两环。module 不反向引用 task_runtime，CAN 帧发送继续由通信任务统一处理。gimbal_yaw_angle 采用 kp、ki、kd、target_deg、actual_deg、enabled，目标和实际角度单位为度；外环输出统一观察 gimbal_yaw_speed.target_rad_s，不重复保存输出字段
- [设计决策] GM6020 yaw 串级以标定的机械正前方为固定零点，模块默认零点为用户实测的 97.0752°，初始化时采纳配置且默认禁用。线性目标范围 [0,360] 度，0°与 360° 是不同目标；原生单圈角减偏置后建立连续位置，PID 内部使用 rad 与 range=0。复用现有调试结构体，独立零点数值与单次采样请求由云台任务串行调用模块处理；主动改变零点后须人工重新使能，仅停用且两环待机并有有效反馈时接受采样，失败请求当次清除。反馈失效只清空连续位置并停机，不清除机械零点；恢复后重新建立单圈相对坐标，确认机械圈数后人工使能，无需重复标定，不自动采用上电位置作为零点
- [设计决策] 底盘采用任务负责 DR16 映射、队列与实测周期，模块只执行 Init/UpdateFeedback/Control/DumpOutput；配置非法或周期超过 100 ms 时整组零输出，单轮离线隔离及自动恢复策略必须明确并单独验证
- [设计决策] 当前云台由 Task_motor_gimbal 调用无 RTOS 依赖的 Gimbal 模块，通过 Gimbal_Output_t 邮箱传递 yaw/pitch 两轴电流 A；CANDevices_ApplyGimbalCurrent 接收两轴电流，先写完 CAN2 ID5/ID6 槽位再统一发送一次 0x2FE。单轴非有限电流归零，命令邮箱空或读失败两轴归零；两轴 enabled=true，默认命令 RELAX。此约定取代历史 yaw 单 float 邮箱、pitch 恒零及模块直接读写邮箱的描述。
- [设计决策] 云台惯性串级控制由 Gimbal 模块接收同帧姿态角、陀螺仪角速度、源采样时间戳及有效标志，INS 任务唯一发布，云台任务只消费邮箱；编码器单独用于机械角和在线检测，惯性故障两轴停机且不回退编码器闭环。当前沿用 INS 安装坐标，yaw 为累计 Yaw/Z，pitch 为 Pitch/Y，直接机体系分量不等同于任意姿态下的欧拉角导数。
- [设计决策] DR16 状态通过独立最新值邮箱分别分发给底盘和云台，不由两个消费者争抢同一队列；Task_Init 集中创建并检查 dr16_gimbal_state，任一路发布失败仍尝试另一路。云台右拨杆中位 RELAX、上位 ANGLE，右摇杆按实际周期累加两轴目标角；输入启用状态由云台任务集中编排，闭环和机械限位保留在 Gimbal 模块。
- [坑/gotcha] 云台单个上部 IMU 的惯性角速度与电机编码器相对转速是不同物理量；手持上部而底座自由时，机械端可以高速反转且 IMU 近零。惯性速度目标限幅和电流限幅不能代替编码器机械超速保护，调试器多字段历史也不能作为原子快照解释。
- [设计决策] yaw 手持调试增加独立机械运动保护：编码器速度幅值大于 12 rad/s，或超过同帧 IMU 三轴角速度模长加 6 rad/s 时，在常规状态机前进入既有 FAULT 并清空两环历史，覆盖起控、ANGLE、SPEED 和 OFFLINE 恢复；任务沿用中位确认后重新使能。这是初始调试约束，不能替代拿起识别、主动制动或正常底座高速稳向的实测核定。
- [约定] 云台控制须逐环明确参考运动、坐标表达、单位和正方向；每环目标与反馈必须一致，跨坐标接口须显式转换。上部陀螺仪测量相对惯性空间的角速度，其分量通常表达在传感器或安装修正后的机体系；机体系 Z 分量不直接等于欧拉 yaw 角导数。编码器测量关节相对底座的角度和转速，改用编码器闭环属于改变控制目标，不能视为无条件等价的大地系转换。用户要求机械运动保护保持闭环工作，不以超速直接进入 FAULT 并联动 RELAX 作为最终方案，具体减速与恢复策略仍需设计验证
- [坑/gotcha] 云台机械运动保护与小陀螺/底盘跟随兼容时，不能把上部惯性速度减编码器相对速度得到的估计再次当成独立底盘测量来放宽同一保护；悬空底座反转也满足该估计。正常旋转包络须结合独立底盘运动依据、几何参数和时效验证，轮速里程计还受打滑与架空影响。该约束不表示待评审的主动制动方案已经实施或验收
- [设计决策] 云台 yaw 运动限速在模块层使用编码器相对转速减上部惯性 yaw 转速加独立底盘实测转速的残差，禁止用同源 base_speed_rad_s 抵消残差；本轮底盘项显式取零，小陀螺与底盘跟随须独立接入后验证。连续电流包络与反向制动不产生 FAULT、不撤销 pitch 控制、不重置姿态目标；速度积分采用限制电流贡献步长的反算，真实故障与单轴反馈超时恢复沿用原状态机。此约定替代历史机械超速直接锁存 FAULT 的处理。
- [设计决策] 云台停转保护在模块层用显式状态机锁存制动与保持，保护期间保留姿态目标并暂停追赶，机械边界后的实际电流用于限步长反算；只有明确失能或RELAX解除，单轴OFFLINE不能解除锁存。未接入四轮实测及底盘最终旋转命令前，小陀螺和跟随兼容不得标为完成；现有无结构体扩展实现仅支持单云台任务实例。
- [设计决策] 云台异常运动保护保留原yaw目标，在制动停稳后继续受限姿态纠偏；编码器与上部IMU运动一致并持续确认，或姿态已到达目标并稳定后，自动渐进恢复速度、电流与原PID输出。恢复期间保留低速残差包络，残差复发立即收回权限；单纯静止不能证明落地，不能只按定时器放开。真实故障、遥控失联及人工恢复联锁保留。此决策替代2026-10-27仅阻尼保持并仅允许RELAX解除的恢复约定；软件模型通过不代表实物稳定，小陀螺与底盘跟随兼容仍未完成。
- [设计决策] 云台保护恢复修正：用户取消保留悬空前yaw目标；制动与停稳阶段跟随当前姿态，残差安静窗口后捕获新姿态并渐进恢复完整PID，静止也能恢复闭环但不能仅凭计时解除低速残差监护。完整PID的GUARDED阶段允许新命令并保持低速包络，编码器与上部IMU持续同向一致才退出监护，残差复发立即撤驱。此决策替代保留旧目标、仅比例保持及先运动后恢复的旧约定；静摩擦只是回归工况，非已确认现场原因。真实故障、遥控失联及人工恢复不变；底盘实测项仍为零，小陀螺与跟随兼容未完成，软件通过不代表实物验收
